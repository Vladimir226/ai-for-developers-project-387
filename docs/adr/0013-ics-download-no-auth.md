# ICS-файл для календаря без авторизации вместо OAuth-синхронизации

**Status:** Accepted
**Drives:** кнопка «Добавить в календарь» (спецификация #9, эндпоинт
`GET /api/v1/bookings/{id}/calendar`)
**Date:** 2026-11-21

**Context:** Встреча не попадает в календарь владельца и гостя: дату, время
и имя приходится переносить руками, звонок легко пропустить. Календари
(Google, Apple, Outlook) умеют импортировать стандартные файлы событий
`.ics` (RFC 5545). Альтернативы — OAuth-синхронизация через Google
Calendar API / Microsoft Graph или подписка на webcal-фид всех броней.
AuthN в системе нет (ADR-0003), деплой — один контейнер без секретов
(ADR-0007); публичность данных броней по UUID уже принята (ADR-0012).

**Decision:** Бронь скачивается как файл `.ics` с одним VEVENT по прямой
ссылке `GET /api/v1/bookings/{id}/calendar` — без OAuth, без новых секретов
и без серверного кода календарных вендоров. UI-кнопка «Добавить в
календарь» — обычная ссылка на эндпоинт (браузерное скачивание): это
осознанное исключение из правила ADR-0004 «UI ходит через SDK» — скачивание
файла есть навигация, а не запрос данных из UI-кода; контракт эндпоинта
(тип `text/calendar; charset=utf-8`, Content-Disposition с именем файла,
404-конверт для неизвестного id) проверяют API-тесты шва 1. Идентификатор
брони — UUID: перебор ссылок не практичнее чтения публичной страницы
предстоящих записей (ADR-0012, ADR-0003).

**Consequences:**

- Проще: нулевые интеграционные ключи, работает в текущем деплое без
  новых секретов (ADR-0007); один файл открывают Google, Apple Calendar и
  Outlook.
- Напоминание даёт сам календарь после импорта — сервис ничего не шлёт.
- Стабильный UID (`<id брони>@book-a-call.local`): повторное скачивание не
  плодит дубликаты события.
- Данные брони (имя, контакт, комментарий) доступны по прямой ссылке любому
  знающему UUID — не шире уже принятой публичности (accepted cost ADR-0003,
  ADR-0012).

**Alternatives:** OAuth-синхронизация с Google Calendar API / Microsoft
Graph (аккаунты и токены в деплое — против ADR-0007, покрывает только
вендоров с API); webcal-подписка на фид всех предстоящих броней (раскрывает
чужие брони разом — шире ADR-0012); шаблонная ссылка «Добавить в Google
Календарь» (один вендор, `.ics` уже покрывает все); email/push-напоминания
от самого сервиса (новая инфраструктура доставки, out of scope #9).

**Revisit when:** появятся реальные (не демо) данные гостей — тогда
подписанные (неугадываемые+проверяемые) ссылки на файл; или понадобится
живая двусторонняя синхронизация календарей — тогда OAuth-интеграция
отдельным ADR.
